Projection Algorithm & Patents

Publicly Stated Methodology

Per LineStar's own GitBook documentation:

  1. Base Projection is computed from historical performance and recent form using statistical models.
  2. Modifiers are applied for matchup, Vegas game environment, weather, injury status, lineup confirmation — over 100 unique factors per athlete.
  3. Real-time updates re-run projections when news breaks (injuries, line moves, weather shifts).
  4. Consensus Projection is offered as an alternative: a weighted average of external industry projections to reduce modeler bias and outlier risk.
  5. Optimizer uses those projections with salary, position, stacking, exposure, and contest-type constraints to produce lineup sets (integer / combinatorial optimization — a variant of the knapsack problem with correlation).

Issued US Patents Referenced by LineStar

LineStar's docs list four issued US patents. Verified via Google Patents:

  • US 9,751,010 — System and method for virtual team assembly (Google Patents). Core claim: base value + modifiers applied to player objects; projected values generated under constraints (salary cap, position caps) and transmitted as lineup data.
  • US 9,744,450 — Listed by LineStar as an additional issued patent covering fantasy lineup optimization. (Google Patents)
  • US 10,478,721 — Listed by LineStar (continuation / improvement). (Google Patents)
  • US 11,660,533 — Listed by LineStar as a more recent issuance. (Google Patents)

⚠ Flag for review: These patents cover specific implementations of lineup assembly systems, not the general idea of fantasy sports or statistical projection. A clean-room implementation that uses standard machine-learning models and standard integer-programming techniques (e.g., MILP via pulp/OR-Tools, genetic algorithms, or Monte Carlo sampling) is generally believed by the open DFS community to be non-infringing, but this is not legal advice. Consult IP counsel before commercial use.

Open Build Plan — Rebuilding the System

A clean-room, free-data implementation path. Each step uses only public / officially licensed data.

Phase 1 — Data Pipeline

  • Ingest historical box scores and advanced stats via open Python libraries: nfl-data-py / nflfastR (nflverse), nba_api, pybaseball, nhl-api-py, sportsipy, ESPN public API endpoints.
  • Daily feed of Vegas odds: The Odds API free tier; ESPN odds endpoints.
  • Weather: Open-Meteo historical + forecast API.
  • Injuries & starting lineups: ESPN public APIs + official league injury report pages.
  • Salaries: scrape/export from DFS lobby pages (for personal research use).
  • News: NewsAPI free tier, RSS beat-writer feeds.
  • Store in a PostgreSQL/SQLite data lake; schedule daily pulls via GitHub Actions.

Phase 2 — Projection Model

  • For each sport, build a per-stat projection model (e.g., for NFL: pass yds, rush yds, targets, TDs, etc.) using:
    • Recent rolling averages (3-, 5-, 10-game windows, weighted by recency)
    • Matchup adjustments (DvP, pace, park/weather factors)
    • Vegas-implied team totals as a calibration anchor
    • Usage / snap / minutes projections from role models
  • Blend with a consensus model: scrape freely available public projections and average.
  • Convert per-stat projections into fantasy points using each platform's scoring rules (DK / FD / Yahoo).
  • Self-healing: nightly back-test that compares projected vs. actual and retrains weights.

Phase 3 — Ownership Model

  • Train a regression (XGBoost / logistic) model on historical actual ownership (from public contests / posted winners) using features: salary, points-per-$ rank, projection rank, Vegas total, team stack appeal, late-news flag.
  • Update up to lock based on news-driven shifts.

Phase 4 — Optimizer

  • Implement as a Mixed Integer Linear Program (MILP) using Google OR-Tools (Apache 2.0) or PuLP (MIT).
  • Constraints: salary cap, position slots, team-stack rules, player groups, exposure caps, correlation (QB-WR stacks, bring-backs).
  • Generate N-lineup sets (1–150) with diversity constraints for GPPs.
  • Cash vs GPP modes: cash maximizes projected points floor; GPP maximizes a leverage score (projection × (1 - ownership)).
  • Late-swap swaptimizer: re-optimize after lock using only players from unfinished games.

Phase 5 — Web App

  • Frontend: React + Vite PWA, or a lightweight static site like this one backed by JSON data files published to GitHub Pages.
  • Backend: FastAPI + Postgres on Fly.io / Render free tier.
  • Daily auto-pull via GitHub Actions cron; results committed back to a data branch for transparency.
  • CSV import/export of projections and lineups (matching LineStar's interface).

Phase 6 — Props AI Equivalent

  • For each player prop on major sportsbooks (from free odds APIs), compute a model projection, compare to the posted line, surface +EV opportunities where model > line by a margin threshold.

Limitations & Open Questions (Flagged for Review)

1. Legal / TOS. Scraping DraftKings, FanDuel, or Yahoo salaries and contest data may violate their Terms of Service. Verify before any automated access. Use official APIs where available; otherwise rely on user-supplied CSV uploads.
2. Patents. LineStar holds four issued US patents on lineup assembly systems (US 9,751,010; 9,744,450; 10,478,721; 11,660,533). We are not copying their proprietary projection coefficients, UI, or proprietary algorithms. We are documenting publicly observable features and rebuilding with standard OR / ML tools. Obtain legal review before commercial launch.
3. Proprietary coefficients are unknown. LineStar does not publish the exact weights of its 100+ factors. Any open model will be an approximation and must be back-tested rigorously against past slates.
4. Real-time data latency. Free APIs have rate limits and lag. LineStar likely pays for premium low-latency feeds (e.g., Sportradar, STATS, FantasyData). Free builds will be minutes behind — material for late-swap and in-game decisions.
5. Ownership ground truth. Actual contest ownership is released by DFS sites after contests settle. Historical datasets are scattered (RotoGrinders, Reddit posts, Twitter); no free bulk API exists. This limits ownership-model training.
6. Beat-reporter sentiment. LineStar aggregates human-sourced info from beat writers and the community (FanSense). Automated news sentiment is a hard NLP problem and adds marginal but real edge.
7. Esports (LoL, CS:GO) & PGA/UFC data. Open historical data is thinner for these sports than for the big four leagues; accuracy will be lower in v1.
8. Sportsbook lines for Props AI. Free odds APIs cover game lines well; player-prop coverage is spotty. Expect to need a paid plan (e.g., OddsJam, Sportradar) for full prop coverage.
9. Mobile apps & push notifications. Native iOS/Android apps are outside the scope of the first web build. A PWA can cover cross-device use initially.
